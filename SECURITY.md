# Security Policy — CASHUP

## Reporting a vulnerability

Do not publish exploit details, credentials, personal data, or customer information in public issues or discussions.

Use GitHub's private vulnerability reporting / security advisory workflow for this repository if it is enabled. If it is unavailable, contact the repository owner through a verified private channel before disclosing technical details.

Include the affected component, impact, reproduction steps, and a safe proof of concept. Do not access, alter, or download other users' data.

## Scope and response

CASHUP is under active development. A public demo is not an invitation to test production systems. Do not perform denial-of-service, social engineering, credential stuffing, destructive testing, or tests against third-party providers.

The maintainers will assess reports, preserve evidence, prioritize remediation, and coordinate disclosure. No response-time guarantee is made while the project is pre-production.

## Secret handling

Never submit live passwords, tokens, API secret keys, service-role keys, database connection strings, recovery codes, or MFA seeds in an issue or report. Revoke and rotate any credential that may have been exposed.
